# משימות — The Tasks Screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `/tasks` — today a stack of one card per task, each with its
own dropdown of every person in the database — with one list grouped by kind:
coverage as `5/8` with avatars and clickable empty slots, gaps first, dates
read against the gate, an assign popover over the season's roster that shows
how loaded each candidate already is, confirmation on the way out of a task and
a way back in, and a new-task drawer that writes `budget_line_id` instead of
the deprecated `budget_amount`.

**Architecture:** The screen is a Server Component that makes five calls
(`listSeasons`, `coverageFor`, `rosterWorkload`, `listEvents`,
`listBudgetLines`) and never queries per row. Everything that can be decided
without a browser — which tasks a view holds, how groups are ordered, how many
avatar chips and empty slots a row shows, what a date means relative to the
gate, which Hebrew sentence a failure maps to — lives in pure modules with node
tests (`src/lib/work/gate.ts`, `src/app/(admin)/tasks/rows.ts`,
`.../failure-messages.ts`). Three client islands carry the interaction the
screen genuinely needs: the assign popover, the row menu, and the new-task
form. `page.tsx` is assembly: it holds no branch that is not covered by a unit
below it.

**Tech Stack:** Next.js 16.3.4 App Router, React 19.2, TypeScript, Drizzle
0.45 + Postgres, CSS Modules. Vitest 5 with `@testing-library/react` under
`/** @vitest-environment jsdom */`; database tests use `src/test/db.ts`
(PGlite). Commands: `npx vitest run <path>`, `npx tsc --noEmit`.

**Spec:** `docs/superpowers/specs/2026-09-17-ui-redesign-design.md` — D9 is the
requirement; R1, R3, R5, R6, R7, R8, R9, R11, A10, A11, A12, C1, C4, C5, C6,
C7, C10, C13, C14, E1, E2, E4, E5 all bind this screen. The domain rules it
must not move are in
`docs/superpowers/specs/2026-09-09-camp-members-fees-design.md` reqs 16–21
(the four kinds, a task's kind-specific fields, assignment statuses, and
uncovered tasks as "accepted assignments fewer than `people_needed`").

## Global Constraints

- **G1 — No new runtime dependencies (spec R1).** No component library, no
  date library, no `@testing-library/user-event`. `fireEvent` and
  `Intl.DateTimeFormat` are what this repo has and what these tests use.
- **G2 — Server Components by default (spec R7).** The three client components
  in this plan each open with a comment saying why it is one. Nothing else in
  `src/app/(admin)/tasks/` carries `'use client'`.
- **G3 — Hebrew only, reused verbatim (spec R9, E5).** Copy that exists today
  in `page.tsx`, `assign-control.tsx` and `new-task-form.tsx` is carried over
  word for word. Every new sentence is Hebrew. No server-action failure echoes
  an `Error.message` — the domain throws English (`a shift needs a time
  window`, `that person was merged into another — assign the survivor`) and
  the action boundary maps it.
- **G4 — Numbers in `<bdi>`, money through `formatILS` (spec A11).** Never
  string-concatenate an amount. Dates in the table are `DD/MM` or `DD/MM/YY`
  with slashes (A12); times are 24-hour `HH:mm`.
- **G5 — The season is a URL parameter (spec R5).** The per-page season `<nav>`
  in `page.tsx:61-71` is deleted. The page reads `?season=<uuid>` and falls
  back to the newest season exactly as `page.tsx:44-45` does today, so it does
  not block on the shell. The top bar's season chip belongs to plan 02; this
  plan does not reach into the shell.
- **G6 — Drawers and views are URLs (spec R6).** `?new=task` opens the
  new-task drawer; `?view=gaps|covered|undated` selects a saved view. No
  client state holds either.

### Rulings (binding — these are the decisions this plan settles)

- **T1 — One list, grouped by kind.** The card-per-task sections
  (`page.tsx:112-144`) and the separate "חסרים אנשים" section
  (`page.tsx:81-110`) both go. One `<table>` with the mock's columns —
  משימה · מתי · צוות · איוש · תקציב · actions — and a group row per kind
  carrying its count. Group order is fixed: `build`, `shift`, `event_task`,
  `deliverable`. Inside a group, open-and-uncovered rows come first, then
  open-and-covered, then closed and cancelled; within a rank, by date
  ascending with undated last, then by title, then by `taskId` — the same
  tie-break `coverageFor` already documents at `coverage.ts:116`, because
  title is not unique among recurring shifts. The mock puts an event task
  inside the משמרות group; that is a mock artifact. The domain has four kinds
  and this groups strictly by `kind`.
- **T2 — Coverage counts `accepted` and `done`, and nothing else.**
  `COUNTS_AS_COVERED` in `src/lib/work/coverage.ts:12` is the rule and stays
  the rule; it gains one exported predicate, `covers(status)`, so the row's
  avatar stack asks the same question the count asks instead of re-listing the
  statuses. A `proposed` assignment gets no chip and closes no gap; it is
  reported as `· הוצעו 2` beside `חסרים 3` and can be accepted from the
  popover. One call per screen, not per row: `coverageFor` already returns
  every assignee in two queries; this plan adds the deliverable's budget line
  and the event's date to the same joins rather than opening a third path.
- **T3 — Dates are read against the gate.** `seasons.startsOn` is nullable, so
  the helper takes `Date | null` and returns `{ kind: 'no-gate' }` for a
  season that has not been dated — the row then shows its date alone and no
  relative line is invented. A task with no date at all shows `בלי תאריך` in
  the "מתי" cell and sorts last. Days are counted as civil days in
  Asia/Jerusalem, not 24-hour spans, so a 23:40 task the night before the gate
  reads `יום אחד לפני השער` and not `0`, and DST cannot shift a count.
- **T4 — The assign popover searches the season's roster.**
  `page.tsx:48-49` hands the control `listPeople(db)`: every unmerged person
  in the database, including people who never joined this season, built with a
  per-person dues settlement the popover throws away. It is replaced by
  `rosterWorkload(db, seasonId)` — the season's memberships, each with the
  number of tasks in this season that person is already on, ordered by that
  load. The mock's "מומלצים — לא משובצים לשום משימה" is not a second model: it
  is the `taskCount === 0` prefix of that one ordering. A season with no
  memberships shows an empty state pointing at `/members`, which is correct
  and is a visible behaviour change from "everyone in the database".
  Several people are assigned in one action.
- **T5 — Every assignment failure gets its own Hebrew sentence (spec R9).**
  `actions.ts:24` collapses every throw into `האדם כבר משובץ למשימה הזו` —
  including `assignPerson`'s refusal of a person who was merged away
  (`coverage.ts:76-78`), which is the one failure a lead can act on and which
  that message tells them to act on backwards. Mapping moves to
  `failure-messages.ts`, keyed on the unique-constraint name
  (`task_assignments_task_person_key`) and on the domain's own wording, with a
  logged generic fallback.
- **T6 — Closing and cancelling confirm; reopening is in scope.** Spec R8
  names cancelling a task and removing an assignment, and both pass through
  `ConfirmDialog`. Reopening is added with them: `setTaskStatus` already
  accepts `'open'`, and a cancel with no way back is exactly the irreversible
  mis-click R8 exists to prevent. Reopening is not destructive and does not
  confirm.
- **T7 — The new-task form moves into a drawer and stops writing
  `budgetAmount`.** `new-task-form.tsx:81` sends `budgetAmount`, which the
  schema already documents as "deprecated in place: kept for existing rows,
  written by nothing" (`src/db/schema/camp.ts`). The drawer sends
  `budgetLineId` instead, picked from the season's budget lines, and
  `createTaskAction`'s input type drops `budgetAmount` so the column cannot be
  written from this screen at all. `createTask` already stores `budgetLineId`,
  so creation needs no second call; `setTaskBudgetLine` is what the row menu
  uses to link a deliverable that already exists — which is the case its own
  docstring describes.
- **T8 — An event task with no events is refused before it is offered.**
  Events are created only by `src/lib/seed/camp-seed.ts:265`; no screen creates
  one. So on a season with no events, picking "משימה באירוע" today leads to a
  select with only `—` in it and a client-side error. The drawer disables that
  kind option and says why. Creating an event from this screen is out of
  scope (the spec's Out of scope names two-sided events for Wave 3).
- **T9 — `summarize`/`seasonCoverageTotals` live here and nowhere else.**
  The home screen's "16 מתוך 32 מקומות" tile (plan 04, D1) and the sidebar's
  משימות count (plan 02, B2) import them from `src/lib/work/coverage.ts`. They
  do not re-derive the arithmetic. `placesFilled` is capped per task at
  `peopleNeeded`, so six people on a task that needs three is a full task and
  not three extra places in the season; without the cap `16 מתוך 32` could
  read `34 מתוך 32`. Only `open` tasks contribute to the places figures, which
  is the same rule `uncovered` already applies at `coverage.ts:152`.
- **T10 — No dead controls.** The mock's `ייצוא` button, its `לפי אדם`
  segmented view and its `שלי` saved view are not built. `שלי` is not
  buildable: an admin is an email (`requireAdmin().email`), and nothing maps
  an email to a `persons` row. A control that cannot work is not rendered.

3. - [ ] Create `src/lib/work/gate.ts`:
   ```ts
   import type { TaskKind } from '@/db/schema/camp';

   /**
    * Dates on the tasks screen are read against one fact: when the gate opens.
    * `20/10` answers nothing on its own; `2 ימים לפני השער` is the sentence a
    * lead acts on. `seasons.starts_on` is nullable, so a season nobody has
    * dated yet gets no relative line at all rather than one invented from
    * today.
    */

   export type GateRelation =
     | { kind: 'before'; days: number }
     | { kind: 'gate-day' }
     | { kind: 'after'; days: number }
     | { kind: 'no-gate' };

   /**
    * The civil date in Israel, as a whole number of days.
    *
    * Comparing civil days rather than 24-hour spans is what makes a 23:40
    * task the night before the gate read `יום אחד לפני השער` instead of `0`,
    * and it sidesteps DST entirely: a civil date has no hours in it to shift.
    * `en-CA` is used only because it formats as `YYYY-MM-DD`.
    */
   function civilDay(date: Date): number {
     const [year, month, day] = new Intl.DateTimeFormat('en-CA', {
       timeZone: 'Asia/Jerusalem', year: 'numeric', month: '2-digit', day: '2-digit',
     }).format(date).split('-').map(Number);
     return Date.UTC(year, month - 1, day) / 86_400_000;
   }

   export function gateRelation(date: Date, gate: Date | null): GateRelation {
     if (!gate) return { kind: 'no-gate' };
     const days = civilDay(date) - civilDay(gate);
     if (days === 0) return { kind: 'gate-day' };
     return days < 0 ? { kind: 'before', days: -days } : { kind: 'after', days };
   }

   /** The date-bearing columns of a task, structurally — so this module stays
    *  free of `coverage.ts` and the two can import each other's shapes without
    *  a cycle. */
   export interface TaskTiming {
     kind: TaskKind;
     startsAt: Date | null;
     endsAt: Date | null;
     dueOn: Date | null;
     eventHeldOn: Date | null;
   }

   export type TaskWhen =
     | { kind: 'window'; startsAt: Date; endsAt: Date }
     | { kind: 'date'; at: Date }
     | { kind: 'none' };

   /**
    * The one "when" a row shows. A shift's window is the most specific answer
    * it has; every other kind falls back to its own deadline, then to a start
    * time if one was set, then to the date of the event it hangs off. A
    * deliverable with none of those is genuinely undated — the רחבה sheet has
    * owned line items with no deadline — and says so rather than borrowing the
    * gate's date.
    */
   export function taskWhen(task: TaskTiming): TaskWhen {
     if (task.kind === 'shift' && task.startsAt && task.endsAt) {
       return { kind: 'window', startsAt: task.startsAt, endsAt: task.endsAt };
     }
     const at = task.dueOn ?? task.startsAt ?? task.eventHeldOn;
     return at ? { kind: 'date', at } : { kind: 'none' };
   }

   /** What the list sorts by. A window sorts by when it starts. */
   export function whenDate(when: TaskWhen): Date | null {
     if (when.kind === 'window') return when.startsAt;
     if (when.kind === 'date') return when.at;
     return null;
   }
   ```

     uncoveredTasks: number;
     placesNeeded: number;

       ),
       datelessTasks: open.filter((row) => taskWhen(row).kind === 'none').length,
       linkedBudgetAgorot: [...lines.values()].reduce((sum, total) => sum + total, 0),
     };
   }

   export interface RosterCandidate {
     personId: string;
     displayName: string;
     /** Tasks in this season this person holds a non-dropped assignment on. */
     taskCount: number;
   }

   /**
    * Who may be assigned, and how loaded they already are.
    *
    * `/tasks` used to hand its assign control `listPeople(db)` — every
    * unmerged person in the database, including people who never joined this
    * season, each one costing a dues settlement the popover then threw away.
    * Staffing ברן 26 means picking from ברן 26's roster. The load count is
    * what turns "who is free" from a memory exercise into a sorted list, and
    * the popover's "מומלצים — לא משובצים לשום משימה" is simply this ordering's
    * `taskCount === 0` head, not a second query.
    */
   export async function rosterWorkload(
     db: AnyDb, seasonId: string,
   ): Promise<RosterCandidate[]> {
     const rows = await db
       .select({
         personId: persons.id,
         displayName: persons.displayName,
         taskCount: countDistinct(tasks.id),
       })
       .from(memberships)
       .innerJoin(persons, eq(persons.id, memberships.personId))
       .leftJoin(taskAssignments, and(
         eq(taskAssignments.personId, persons.id),
         ne(taskAssignments.status, 'dropped'),
       ))
       // The season lives on the join, not in the where: a member with no
       // assignment at all must still come back, with a count of zero.
       .leftJoin(tasks, and(
         eq(tasks.id, taskAssignments.taskId),
         eq(tasks.seasonId, seasonId),
       ))
       .where(and(
         eq(memberships.seasonId, seasonId),
         // A merged-away person is invisible everywhere else (`listPeople`,
         // `resolveName`) and `assignPerson` refuses them — offering them here
         // would be offering a refusal.
         isNull(persons.mergedIntoId),
       ))
       .groupBy(persons.id, persons.displayName)
       .orderBy(asc(persons.displayName));

     // Sorted in JS rather than by the aggregate: the SQL order is the stable
     // tie-break, and `Array.prototype.sort` is stable, so equal loads stay in
     // name order.
     return [...rows].sort((a, b) => a.taskCount - b.taskCount);
   }

   export const KIND_ORDER: TaskKind[] = ['build', 'shift', 'event_task', 'deliverable'];

   export const KIND_LABELS: Record<TaskKind, string> = {
     build: 'הקמה ולוגיסטיקה',
     shift: 'משמרות',
     event_task: 'משימות באירועים',
     deliverable: 'אחריות תקציבית',

   export const KIND_ROW_LABELS: Record<TaskKind, string> = {

     shift: 'משמרת',
     event_task: 'משימה באירוע',
     deliverable: 'אחריות על סעיף תקציב',
   };

   export const TASK_STATUS_LABELS: Record<TaskStatus, string> = {
     open: 'פתוחה',
     done: 'הושלמה',
     cancelled: 'בוטלה',
   };

   export type TaskView = 'all' | 'gaps' | 'covered' | 'undated';
   const VIEWS: TaskView[] = ['all', 'gaps', 'covered', 'undated'];

   /** A view that is not one of ours is the whole list, not a 404: the value
    *  comes from a URL a lead may have edited by hand. */
   export function asTaskView(value: string | undefined): TaskView {
     return VIEWS.includes(value as TaskView) ? (value as TaskView) : 'all';
   }

   export function filterTasks(rows: TaskCoverage[], view: TaskView): TaskCoverage[] {
     if (view === 'gaps') return rows.filter((row) => row.uncovered);
     if (view === 'covered') {
       return rows.filter((row) => row.status === 'open' && !row.uncovered);
     }
     if (view === 'undated') {
       return rows.filter((row) => row.status === 'open' && taskWhen(row).kind === 'none');
     }
     return rows;
   }

   export interface TaskGroup { kind: TaskKind; label: string; rows: TaskCoverage[] }

   /** Open gaps, then open and staffed, then everything closed or cancelled. */
   function rank(row: TaskCoverage): number {
     if (row.status !== 'open') return 2;
     return row.uncovered ? 0 : 1;
   }

   function compare(a: TaskCoverage, b: TaskCoverage): number {
     if (rank(a) !== rank(b)) return rank(a) - rank(b);
     const left = whenDate(taskWhen(a));
     const right = whenDate(taskWhen(b));
     if (left && right && left.getTime() !== right.getTime()) {
       return left.getTime() - right.getTime();
     }
     // An undated task sorts last within its rank rather than first, which is
     // where a null would otherwise put it.
     if (!left !== !right) return left ? -1 : 1;
     // `taskId` breaks the last tie for the same reason `coverageFor` orders
     // by it: a recurring `משמרת בר` shares its title with its siblings.
     return a.title.localeCompare(b.title, 'he') || a.taskId.localeCompare(b.taskId);
   }

   export function groupByKind(rows: TaskCoverage[]): TaskGroup[] {
     return KIND_ORDER
       .map((kind) => ({
         kind,
         label: KIND_LABELS[kind],
         rows: rows.filter((row) => row.kind === kind).sort(compare),
       }))
       .filter((group) => group.rows.length > 0);
   }

   export type Tone = 'ok' | 'warn' | 'bad' | 'neutral';

   /** Spec R3: the tone never carries the meaning on its own — the cell always
    *  prints `חסרים 3` or `מאויש` beside the figure. */
   export function coverageTone(row: TaskCoverage): Tone {
     if (row.status !== 'open') return 'neutral';
     if (row.accepted >= row.peopleNeeded) return 'ok';
     return row.accepted === 0 ? 'bad' : 'warn';
   }

   export interface StackSlots {
     avatars: Assignee[];
     /** Dashed places still to fill. The first one is the button. */
     empty: number;
     /** Places beyond the cap, shown as `+3`. */
     overflow: number;
   }

   /**
    * The avatar stack: one chip per person who actually covers the task, then
    * one dashed chip per missing place, capped so a task needing twelve does
    * not take the column over. A `proposed` assignment gets no chip, because
    * it fills no place — it appears in the popover with its `אישר` button.
    */
   export function stackSlots(row: TaskCoverage, cap = 5): StackSlots {
     const covering = row.assignees.filter((assignee) => covers(assignee.status));
     const missing = Math.max(0, row.peopleNeeded - covering.length);
     const total = covering.length + missing;
     const shown = Math.min(total, cap);
     const avatars = covering.slice(0, shown);
     return { avatars, empty: shown - avatars.length, overflow: total - shown };
   }

   export function proposedCount(row: TaskCoverage): number {
     return row.assignees.filter((assignee) => assignee.status === 'proposed').length;
   }

   /**
    * Every link on this screen keeps the season (spec R5) and carries the
    * drawer in the URL (R6). Built rather than templated so no call site can
    * forget the season and quietly send a lead to a different year.
    */
   export function tasksHref(
     current: { season?: string; view?: string },
     change: { view?: TaskView | null; open?: 'new' | null },
   ): string {
     const params = new URLSearchParams();
     if (current.season) params.set('season', current.season);
     const view = change.view === undefined ? asTaskView(current.view) : change.view;
     if (view && view !== 'all') params.set('view', view);
     if (change.open === 'new') params.set('new', 'task');
     const query = params.toString();
     return query ? `/tasks?${query}` : '/tasks';
   }

    * A client component because staffing a task is a conversation, not a

    * in one action. Holding the search text and the ticks in the URL would put
    * a history entry behind every keystroke.

    * (`rosterWorkload`), computed once for the whole page. The old control
    * took `listPeople(db)` — every person in the database — and offered no way
    * to tell who was already carrying four shifts.
    */

   import { useRouter } from 'next/navigation';
   import { normalizeHebrew } from '@/lib/text/normalize';
   import type { Assignee, RosterCandidate } from '@/lib/work/coverage';
   import { Avatar } from '@/components/ui/avatar';
   import { ConfirmDialog } from '@/components/ui/confirm-dialog';
   import { EmptyState } from '@/components/ui/empty-state';
   import { Icon } from '@/components/icon';
   import {
     assignPeopleAction, setAssignmentStatusAction, removeAssignmentAction,
   } from './actions';
   import styles from './tasks.module.css';

   const STATUS_LABELS: Record<string, string> = {
     proposed: 'הוצע',
     accepted: 'אישר',
     done: 'בוצע',
     dropped: 'ירד',
   };

   export function AssignPopover({
     taskId, title, seasonName, peopleNeeded, accepted, assignees, candidates,
     variant = 'button',
   }: {
     taskId: string;
     title: string;
     seasonName: string;
     peopleNeeded: number;
     accepted: number;
     assignees: Assignee[];
     candidates: RosterCandidate[];
     variant?: 'button' | 'slot';
   }) {

     const [open, setOpen] = useState(false);
     const [query, setQuery] = useState('');
     const [picked, setPicked] = useState<string[]>([]);
     const [removing, setRemoving] = useState<Assignee | null>(null);
     const [error, setError] = useState<string | null>(null);
     const [pending, startTransition] = useTransition();
     const trigger = useRef<HTMLButtonElement>(null);

     useEffect(() => {
       if (!open) return undefined;
       function onKey(event: KeyboardEvent) {
         if (event.key === 'Escape') { setOpen(false); trigger.current?.focus(); }
       }
       document.addEventListener('keydown', onKey);
       return () => document.removeEventListener('keydown', onKey);
     }, [open]);

     function run(action: () => Promise<{ ok: boolean; error?: string }>) {
       setError(null);
       startTransition(async () => {
         const result = await action();
         if (!result.ok) { setError(result.error ?? 'שגיאה'); return; }
         setPicked([]);
         setOpen(false);
         router.refresh();
       });
     }

     const needle = normalizeHebrew(query);
     const matching = candidates.filter(
       (candidate) => !needle || normalizeHebrew(candidate.displayName).includes(needle),
     );

     // of one ordering rather than two queries.
     const free = matching.filter((candidate) => candidate.taskCount === 0);
     const loaded = matching.filter((candidate) => candidate.taskCount > 0);

     function toggle(personId: string) {
       if (onTask.has(personId)) return;
       setPicked((current) => (current.includes(personId)
         ? current.filter((id) => id !== personId)
         : [...current, personId]));
     }

       const already = onTask.has(candidate.personId);
       return (
         <button
           key={candidate.personId}

           ref={trigger}

             </p>

                         )}

                       </button>
                     )}
                     <button type="button" disabled={pending} onClick={() => setRemoving(assignee)}>
                       הסר
                     </button>
                   </li>

                     value={query}
                     placeholder="חיפוש חבר…"

                   />
                 </label>

                 {free.length > 0 && (
                   <>

                     {`שיבוץ ${picked.length}`}

               </>

             {error && <p className="badge-warn" role="alert">{error}</p>}
           </div>

             setRemoving(null);

           }}
         />
       </div>

   /**
    * A client component because spec R8 makes closing and cancelling a task
    * pass through a confirmation, and a confirmation is a dialog with focus
    * and an answer — not a link.
    *

    * `'open'`; nothing ever offered it, so a cancelled task was cancelled for
    * good. A cancel that cannot be undone is exactly the irreversible
    * mis-click R8 exists to prevent, so the way back ships with the
    * confirmation. Reopening is not destructive and does not confirm.
    */

   import { useState, useTransition } from 'react';
   import { useRouter } from 'next/navigation';
   import type { TaskKind, TaskStatus } from '@/db/schema/camp';
   import { ConfirmDialog } from '@/components/ui/confirm-dialog';
   import { Field } from '@/components/ui/field';
   import { Icon } from '@/components/icon';
   import { setTaskStatusAction, setTaskBudgetLineAction } from './actions';
   import styles from './tasks.module.css';

   type Pending = 'close' | 'cancel' | null;

   export function TaskMenu({
     taskId, title, status, kind, accepted, hasBudgetLine, budgetLines,
   }: {
     taskId: string;
     title: string;
     status: TaskStatus;
     kind: TaskKind;
     accepted: number;
     hasBudgetLine: boolean;
     budgetLines: Array<{ id: string; label: string }>;
   }) {
     const router = useRouter();
     const [open, setOpen] = useState(false);
     const [confirming, setConfirming] = useState<Pending>(null);
     const [lineId, setLineId] = useState('');
     const [error, setError] = useState<string | null>(null);
     const [pending, startTransition] = useTransition();

     function run(action: () => Promise<{ ok: boolean; error?: string }>) {
       setError(null);
       startTransition(async () => {
         const result = await action();
         if (!result.ok) { setError(result.error ?? 'שגיאה'); return; }
         setOpen(false);
         router.refresh();
       });
     }

     const offersBudgetLine = kind === 'deliverable' && !hasBudgetLine
       && budgetLines.length > 0;

     return (
       <div className={styles.popoverHost}>
         <button
           type="button"
           className={styles.iconButton}
           aria-label="אפשרויות"
           aria-expanded={open}
           onClick={() => setOpen((current) => !current)}
         >
           <Icon name="more" size={15} />
         </button>

         {open && (
           <div className={styles.menu} role="menu" aria-label={`אפשרויות — ${title}`}>

                   בטל משימה

                 type="button"
                 disabled={pending}
                 onClick={() => run(() => setTaskStatusAction(taskId, 'open'))}

                   <select value={lineId} onChange={(event) => setLineId(event.target.value)}>
                     <option value="">—</option>
                     {budgetLines.map((line) => (
                       <option key={line.id} value={line.id}>{line.label}</option>
                     ))}
                   </select>
                 </Field>
                 <button
                   type="button"
                   disabled={!lineId || pending}
                   onClick={() => run(() => setTaskBudgetLineAction(taskId, lineId))}
                 >
                   שייך
                 </button>
               </div>
             )}

             {error && <p className="badge-warn" role="alert">{error}</p>}
           </div>
         )}

         <ConfirmDialog
           open={confirming === 'close'}
           title={`לסגור את המשימה "${title}"?`}
           body="המשימה תיסמן כהושלמה ותצא מספירת האיוש. אפשר לפתוח אותה מחדש."
           confirmLabel="סגור"
           onCancel={() => setConfirming(null)}
           onConfirm={() => {
             setConfirming(null);
             run(() => setTaskStatusAction(taskId, 'done'));
           }}
         />

           open={confirming === 'cancel'}
           title={`לבטל את המשימה "${title}"?`}

             <>
               <bdi>{accepted}</bdi>
               {' שיבוצים יישארו רשומים, אך המשימה תצא מספירת האיוש. '}

             </>
           )}
           confirmLabel="בטל"
           tone="danger"
           onCancel={() => setConfirming(null)}
           onConfirm={() => {
             setConfirming(null);
             run(() => setTaskStatusAction(taskId, 'cancelled'));
           }}
         />
       </div>
