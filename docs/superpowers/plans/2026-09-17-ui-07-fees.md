# UI 07 — דמי קאמפ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild `/fees` as the screen the camp actually uses every week: four rollup figures that double as filters, one table whose row carries its own verb, a payment drawer that finally offers the **account** the model has carried since Wave 1, a "שמירה ומעבר לבא" that turns collection into a run, exceptions as their own named action rather than a form buried in a cell, a confirmation before a payment is deleted, and Hebrew — not English — on every refusal.

**Why now:** `/fees` today has one column called **שינוי** that holds three different things at once: an exception form, a four-field payment form, and the payment list (`src/app/(admin)/fees/member-fee-row.tsx:177-258`). Every one of the thirty-five rows renders all three, so the table is unreadable and a lead cannot see who still owes. Three defects sit underneath that:

- **Every payment typed on this screen is unattributed money.** `payment.account_id` exists (`src/db/schema/camp.ts:120`), `PaymentInput.accountId` exists (`src/lib/fees/payments.ts:18`), `accountBalances` reads it (`src/lib/money/accounts.ts:81-84`), and `unattributedAgorot` exists to report the damage (`src/lib/money/accounts.ts:120`). The UI has never offered the field, and `recordPaymentAction` does not even accept it (`src/app/(admin)/fees/actions.ts:92-98`). Every shekel a lead has typed into this screen counts toward collection and toward no קופה.
- **Deleting a payment is one click with no confirmation** (`member-fee-row.tsx:249-255`), against R8.
- **English reaches a Hebrew screen.** `failed()` passes `error.message` straight through (`actions.ts:13-15`), and the libraries throw `an exception must carry a reason`, `no due for that person in that season — issue the flat dues first`, `a payment amount must be positive` and six more, all in English, all rendered into `role="alert"` on a Hebrew page. Against R9.

**Architecture:** A Server Component page (`src/app/(admin)/fees/page.tsx`) reads the season from `?season=` (R5 — the per-page season nav at `page.tsx:40-50` is deleted; the shell owns the switcher), calls `seasonFeeSummary` once and `listSeasonFees` once, and composes four server-rendered pieces: `FeeRollup` (tiles), `FeeViews` (the saved-view tab strip), `FeeTable` (the table and its totals row), and at most one URL-driven drawer. Filtering, counting, the row's payment state and the "next unpaid member" all live in one pure, tested module, `src/lib/fees/views.ts`, so a tile, a tab and the table can never disagree about what "טרם שילמו" means. Three client components exist and each says why in a comment: the payment drawer, the exception drawer, and the two buttons that call an action from a row (`IssueDueButton`, `IssueMissingDuesButton`). Drawers are search params (R6), so a lead can send `"/fees?season=…&pay=…"` to another lead. Hebrew refusal text is produced at the action boundary by `toHebrewError`, and a message with no mapping renders the generic Hebrew fallback and is logged (R9).

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Drizzle + Postgres, CSS Modules. Vitest + `@testing-library/react` with `/** @vitest-environment jsdom */` for component tests; `src/test/db.ts` (PGlite) for database tests. ## Rulings (binding, settled before any code)

**V — The views.** Seven views, each a `?view=` value. They are filters, not a partition: `exception` and `offset` deliberately overlap the others.

| `?view=` | label | a row matches when |
|---|---|---|
| `all` | הכול | always |
| `unpaid` | טרם שילמו | there is a due, the amount is above zero, and nothing has been paid |
| `partial` | שילמו חלקית | there is a due, something has been paid, and something is still outstanding |
| `paid` | שולם | there is a due and nothing is outstanding — including a zero-amount exception |
| `exception` | חריגים | `kind === 'exception'` |
| `offset` | קוזזו | at least one payment on the due has channel `קיזוז` |
| `nodue` | בלי חיוב | no due has been issued |

An unknown or absent `?view=` is `all`. `view=all` is omitted from generated URLs, so the canonical link to this screen stays `"/fees?season=…"`.

**T — Which view each tile links to.** צפי גבייה → `all`. נגבה → `paid`. נותר לגבות → `unpaid`. נגבה בקיזוז → `offset`. The mock's fourth tile has no tab to land on; `offset` is that tab, and it is the seventh entry in the strip. The נותר tile's value is the whole outstanding total, which spans `unpaid` and `partial`, so its derivation line names both counts — `9 טרם שילמו · 3 שילמו חלקית` — and its single link goes to `unpaid`, which is where a lead's next action is. A number never appears on that tile as one unlinked claim.

**G — No gendered copy.** The mock writes `טרם שילם` and `טרם שילמה`. `persons` has no gender column and inferring one from a Hebrew first name is exactly the guessing this system refuses. Every state word is written about the **due**, not the person: `טרם שולם`, `שולם 500 ₪`, `שולם`, `שולם בקיזוז`, `אין מה לגבות`, `אין חיוב`.

**A — The account picker.** Populated from `listOpenAccounts(db)` — every account whose `closed_at` is null, in name order. **Nothing is pre-selected.** The first option is `בלי קופה`, and it is the initial value. Leaving it there is allowed and is an explicit choice: the payment saves, counts toward collection, and enters no account balance. The screen says so twice — as the field's hint, verbatim from the mock, `בלי קופה הסכום ייספר בגבייה אבל לא ביתרה של אף חשבון.`, and again in the save confirmation. The page carries a warn banner whenever the season holds any such money. Choosing an account whose `kind` is `personal` shows `זה חשבון פרטי של חבר קאמפ, לא קופה של הקאמפ.` beneath the field. Defaulting to "the last account used" was considered and refused: a default that is right four times out of five produces a wrong attribution that nobody will ever notice.

**K — קיזוז keeps its two rules.** Selecting `קיזוז` disables the account field and forces it to `בלי קופה` (`recordPayment` throws `קיזוז אינו מזיז מזומן, ולכן אינו נכנס לחשבון` — already Hebrew, and it passes through the mapper untouched), and makes the note mandatory with the existing message.

**N — "שמירה ומעבר לבא".** The next member is the first row **after the current one in the table's order** (which is `listRoster`'s display-name order) that both has an outstanding balance and matches the current view. It is computed on the server from the same row list the table rendered and handed to the drawer as one id, so the client holds no list. There is no wrap-around: when there is no next, the drawer stays open on a done state reading `זה היה האחרון ברשימה.` and the save confirmation stays visible.

**X — The exception is an action, not a cell.** It lives at `?exception=<personId>` in its own drawer, with an amount, a reason that cannot be empty, and the signed-in lead recorded as the decider. The table shows an existing exception inline as a brand pill plus `{reason} · {decidedBy}`, read-only. Clearing an exception discards a recorded reason, so it confirms (R8).

**M — No overflow menu.** The mock's `⋯` button is not built this round. A row has exactly two controls — its verb and `הגדרת חריג` / `עריכת החריג` — and two controls do not need a menu. They are always in the DOM and always focusable; CSS reveals them on `:hover` and `:focus-within` with `opacity`, never `display: none` (E4).

**C — Copy.** Validation and refusal messages are reused **verbatim** from the existing code. Labels, headings and hints follow the mock. Every string this plan introduces or changes is listed in the task that introduces it.

```ts
/**
 * Server actions return Hebrew, because they are read on a Hebrew screen.
 *
 * The domain libraries throw in English — `an exception must carry a reason` —
 * and `failed()` used to hand that message straight to `role="alert"`. This is
 * the boundary where that stops (R9).
 *
 * Order matters. The map is consulted first, by prefix, because three of the
 * thrown messages interpolate an id and one of them, `unknown payment
 * channel: מזומן`, contains a Hebrew letter while being an English message.
 * Only a message that matches nothing is tested for Hebrew; if it carries
 * Hebrew it was written for a lead and passes through unchanged. Anything else
 * is logged once and replaced. A raw message is never echoed to the screen.
 */

export const HEBREW_FALLBACK = 'משהו השתבש. הפעולה לא נשמרה.';

/** Hebrew letters, `א`–`ת` and the cantillation block around them. */
const HEBREW_LETTER = /[֐-׿]/;

export type HebrewErrors = ReadonlyArray<readonly [prefix: string, hebrew: string]>;

export function toHebrewError(error: unknown, map: HebrewErrors): string {
  const message = error instanceof Error ? error.message : String(error);

  const hit = map.find(([prefix]) => message.startsWith(prefix));
  if (hit) return hit[1];

  if (HEBREW_LETTER.test(message)) return message;

  console.error('unmapped server error', message);
  return HEBREW_FALLBACK;
}
```

```ts
import type { MemberFeeRow } from '@/lib/fees/season-fees';
import type { PaymentRow } from '@/lib/fees/payments';

/**
 * What "טרם שילמו" means, in one place.
 *
 * A tile, a tab and a table row on `/fees` all answer the same question, and
 * before this module each of them answered it with its own inline predicate.
 * Everything here is pure and takes the rows the page already fetched, so the
 * number on a tab and the rows under it cannot drift apart.
 *
 * The views are filters, not a partition: `exception` and `offset` overlap the
 * others on purpose. `all` is the default and is left out of generated URLs.
 */
export type FeeView =
  | 'all' | 'unpaid' | 'partial' | 'paid' | 'exception' | 'offset' | 'nodue';

export const FEE_VIEWS: ReadonlyArray<{ id: FeeView; label: string }> = [
  { id: 'all', label: 'הכול' },
  { id: 'unpaid', label: 'טרם שילמו' },
  { id: 'partial', label: 'שילמו חלקית' },
  { id: 'paid', label: 'שולם' },
  { id: 'exception', label: 'חריגים' },
  { id: 'offset', label: 'קוזזו' },
  { id: 'nodue', label: 'בלי חיוב' },
];

export function parseFeeView(value: string | undefined): FeeView {
  const hit = FEE_VIEWS.find((view) => view.id === value);
  return hit ? hit.id : 'all';
}

/**
 * The word the row's pill carries. Written about the due rather than the
 * person: `persons` has no gender column, and guessing one from a Hebrew first
 * name is exactly what this system refuses to do.
 */
export type PaymentState =
  | 'nodue' | 'nothing-to-collect' | 'unpaid' | 'partial' | 'paid' | 'paid-by-offset';

export function paymentStateOf(row: MemberFeeRow): PaymentState {
  if (row.dueId === null) return 'nodue';
  if (row.amountAgorot === 0) return 'nothing-to-collect';
  if (row.outstandingAgorot > 0) return row.paidAgorot > 0 ? 'partial' : 'unpaid';
  const offsetOnly = row.payments.length > 0
    && row.payments.every((entry) => entry.channel === 'קיזוז');
  return offsetOnly ? 'paid-by-offset' : 'paid';
}

export function matchesView(row: MemberFeeRow, view: FeeView): boolean {
  const state = paymentStateOf(row);
  switch (view) {
    case 'all': return true;
    case 'unpaid': return state === 'unpaid';
    case 'partial': return state === 'partial';
    case 'paid':
      return state === 'paid' || state === 'paid-by-offset'
        || state === 'nothing-to-collect';
    case 'exception': return row.kind === 'exception';
    case 'offset': return row.payments.some((entry) => entry.channel === 'קיזוז');
    case 'nodue': return state === 'nodue';
  }
}

export function rowsForView(rows: MemberFeeRow[], view: FeeView): MemberFeeRow[] {
  return rows.filter((row) => matchesView(row, view));
}

export function viewCounts(rows: MemberFeeRow[]): Record<FeeView, number> {
  const counts = Object.fromEntries(
    FEE_VIEWS.map((view) => [view.id, 0]),
  ) as Record<FeeView, number>;
  for (const row of rows) {
    for (const view of FEE_VIEWS) {
      if (matchesView(row, view.id)) counts[view.id] += 1;
    }
  }
  return counts;
}

/** Has a due, and something is still owed on it. */
export function isPayable(row: MemberFeeRow): boolean {
  return row.dueId !== null && row.outstandingAgorot > 0;
}

/**
 * The next member of a collection run: the first row after this one, in the
 * table's own order, that still owes something and belongs to the view on
 * screen.
 *
 * The anchor is looked up in the **unfiltered** list on purpose. After a
 * payment is saved the page re-renders, and the member who was just paid off
 * may no longer match the view — looking the anchor up inside the filtered
 * list would then find nothing and silently send the lead back to the top.
 */
export function nextPayable(
  rows: MemberFeeRow[], view: FeeView, afterPersonId: string,
): string | null {
  const at = rows.findIndex((row) => row.personId === afterPersonId);
  if (at === -1) return null;
  for (let i = at + 1; i < rows.length; i += 1) {
    if (isPayable(rows[i]) && matchesView(rows[i], view)) return rows[i].personId;
  }
  return null;
}

/** `1 מתוך 9`. `index` is 0 when this row is not one of the payable ones. */
export function payablePosition(
  rows: MemberFeeRow[], view: FeeView, personId: string,
): { index: number; total: number } {
  const payable = rows.filter((row) => isPayable(row) && matchesView(row, view));
  const at = payable.findIndex((row) => row.personId === personId);
  return { index: at === -1 ? 0 : at + 1, total: payable.length };
}

/** `listPayments` orders by `paid_on` ascending, so the last one is the latest. */
export function lastPaymentOf(row: MemberFeeRow): PaymentRow | null {
  return row.payments.length === 0 ? null : row.payments[row.payments.length - 1];
}
```

```ts
import type { FeeView } from '@/lib/fees/views';

/**
 * Every link this screen produces, from one place.
 *
 * A drawer is a URL (R6) and the season is global (R5), so a link to "record
 * איתי's payment, in the טרם שילמו view, for ברן 26" is a thing a lead can
 * paste into a message. Building these by hand at six call sites is how one
 * of them ends up dropping `?season=`.
 */
export interface FeesHrefParts {
  season: string;
  view?: FeeView;
  pay?: string;
  exception?: string;
}

export function feesHref(parts: FeesHrefParts): string {
  const params = new URLSearchParams({ season: parts.season });
  if (parts.view && parts.view !== 'all') params.set('view', parts.view);
  // One drawer at a time: two overlapping panels have no sensible layout, and
  // `pay` is the one a lead is far more often in the middle of.
  if (parts.pay) params.set('pay', parts.pay);
  else if (parts.exception) params.set('exception', parts.exception);
  return `/fees?${params.toString()}`;
}
```

```tsx
'use client';

/**
 * A client component because recording a payment is a form: the amount, the
 * channel and the account depend on each other while the lead is typing —
 * choosing קיזוז takes the account away and makes the note mandatory — and
 * "שמירה ומעבר לבא" has to navigate after the save resolves. None of that can
 * be expressed as a server round trip per keystroke.
 *
 * The drawer itself is a URL (R6): the server decides it is open from
 * `?pay=<personId>` and hands this component everything it needs, including
 * the id of the next member of the run. No list lives on the client.
 */

import { useState } from 'react';
import type { FormEvent } from 'react';
import { useRouter } from 'next/navigation';
import Link from 'next/link';
import { Drawer } from '@/components/ui/drawer';
import { Field, Segmented } from '@/components/ui/field';
import { Banner } from '@/components/ui/banner';
import { Icon } from '@/components/ui/icon';
import { formatILS } from '@/lib/money';
import { isBlank } from '@/lib/text/normalize';
import { PAYMENT_CHANNELS } from '@/db/schema/camp';
import type { PaymentChannel } from '@/db/schema/camp';
import type { AccountKind } from '@/db/schema/money';
import type { MemberFeeRow } from '@/lib/fees/season-fees';
import type { FeeView } from '@/lib/fees/views';
import { recordPaymentAction } from './actions';
import { feesHref } from './href';
import styles from './fees.module.css';

export interface AccountOption { id: string; name: string; kind: AccountKind }

/** Today as an `<input type="date">` value, in the viewer's own time zone. */
function todayInputValue(): string {
  const now = new Date();
  const local = new Date(now.getTime() - now.getTimezoneOffset() * 60_000);
  return local.toISOString().slice(0, 10);
}

/** `DD/MM/YY` with slashes — what Excel and the banks show (A12). */
function formatShortDate(date: Date): string {
  const dd = String(date.getDate()).padStart(2, '0');
  const mm = String(date.getMonth() + 1).padStart(2, '0');
  const yy = String(date.getFullYear()).slice(2);
  return `${dd}/${mm}/${yy}`;
}

export function PaymentDrawer({
  row, seasonId, view, accounts, recordedBy, nextPersonId, prevPersonId, position,
}: {
  row: MemberFeeRow;
  seasonId: string;
  view: FeeView;
  flatRateAgorot: number;
  accounts: AccountOption[];
  recordedBy: string;
  nextPersonId: string | null;
  prevPersonId: string | null;
  position: { index: number; total: number };
}) {
  const router = useRouter();
  const [amount, setAmount] = useState(String((row.outstandingAgorot || 0) / 100));
  const [channel, setChannel] = useState<PaymentChannel>(PAYMENT_CHANNELS[0]);
  const [paidOn, setPaidOn] = useState(todayInputValue());
  const [accountId, setAccountId] = useState('');
  const [note, setNote] = useState('');
  const [pending, setPending] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const [saved, setSaved] = useState<string | null>(null);

  const closeHref = feesHref({ season: seasonId, view });
  const isOffset = channel === 'קיזוז';
  const chosen = accounts.find((account) => account.id === accountId) ?? null;

  function pickChannel(next: PaymentChannel) {
    setChannel(next);
    // קיזוז moves no cash, so it must never carry an account. Clearing it here
    // rather than at submit keeps the screen honest about what will be saved.
    if (next === 'קיזוז') setAccountId('');
  }

  async function save(step: boolean) {
    setError(null);
    setSaved(null);

    const parsed = Number(amount);
    if (!Number.isFinite(parsed) || parsed <= 0) {
      setError('סכום התשלום חייב להיות מספר חיובי.');
      return;
    }
    if (isOffset && isBlank(note)) {
      setError('קיזוז חייב לכלול הערה שמסבירה מול מה הוא קוזז — אחרת אי אפשר לדעת בעתיד.');
      return;
    }

    setPending(true);
    try {
      const result = await recordPaymentAction({
        dueId: row.dueId!,
        amount: parsed,
        channel,
        paidOn,
        note: isBlank(note) ? undefined : note,
        accountId: accountId === '' ? undefined : accountId,
      });
      if (!result.ok) { setError(result.error); return; }

      const unplaced = !isOffset && accountId === ''
        ? ' הסכום נספר בגבייה אבל לא נכנס ליתרה של אף קופה.' : '';
      const ending = step && nextPersonId === null ? ' זה היה האחרון ברשימה.' : '';
      setSaved(`נרשמו ${formatILS(Math.round(parsed * 100))} ₪ עבור ${row.displayName}.${unplaced}${ending}`);
      setNote('');

      if (step && nextPersonId) {
        router.replace(feesHref({ season: seasonId, view, pay: nextPersonId }));
      }
      // The action revalidated `/fees`; this repaints the table underneath.
      router.refresh();
    } finally {
      setPending(false);
    }
  }

  function onSubmit(event: FormEvent) { event.preventDefault(); save(false); }

  if (row.dueId === null) {
    return (
      <Drawer
        title={`רישום תשלום — ${row.displayName}`}
        closeHref={closeHref}
        footer={<Link className={styles.btn} href={closeHref}>סגירה</Link>}
      >
        <p className={styles.muted}>
          אין עדיין חיוב ל{row.displayName}. צריך להנפיק חיוב לפני שאפשר לרשום תשלום.
        </p>
      </Drawer>
    );
  }

  return (
    <Drawer
      title={`רישום תשלום — ${row.displayName}`}
      subtitle={(
        <>
          {row.kind === 'exception' ? 'חריג' : 'תעריף רגיל'}
          {' · נותר '}
          <bdi>{formatILS(row.outstandingAgorot)} ₪</bdi>
        </>
      )}
      closeHref={closeHref}
      stepper={{
        index: position.index,
        total: position.total,
        prevHref: prevPersonId ? feesHref({ season: seasonId, view, pay: prevPersonId }) : null,
        nextHref: nextPersonId ? feesHref({ season: seasonId, view, pay: nextPersonId }) : null,
      }}
      footer={(
        <>
          <button type="submit" form="payment-form" className={styles.btnPrimary} disabled={pending}>
            רישום התשלום
          </button>
          <button
            type="button"
            className={styles.btn}
            disabled={pending}
            onClick={() => save(true)}
          >
            שמירה ומעבר לבא
          </button>
          <span className={styles.grow} />
          <span className={styles.muted}>יירשם על שמך · {recordedBy}</span>
        </>
      )}
    >
      <form id="payment-form" onSubmit={onSubmit} className={styles.drawerForm}>
        <div className={styles.twoUp}>
          <Field label="סכום" htmlFor="pay-amount" hint="מלא את היתרה. אפשר גם סכום חלקי.">
            <input
              id="pay-amount" type="number" min="0.01" step="0.01" inputMode="decimal"
              value={amount} onChange={(event) => setAmount(event.target.value)}
            />
          </Field>
          <Field label="תאריך התשלום" htmlFor="pay-date" hint="היום">
            <input
              id="pay-date" type="date"
              value={paidOn} onChange={(event) => setPaidOn(event.target.value)}
            />
          </Field>
        </div>

        <Segmented
          label="אמצעי תשלום"
          options={PAYMENT_CHANNELS}
          value={channel}
          onChange={pickChannel}
        />

        <Field
          label="לאיזו קופה הכסף נכנס"
          htmlFor="pay-account"
          hint={isOffset
            ? 'קיזוז אינו מזיז מזומן, ולכן אינו נכנס לקופה.'
            : 'בלי קופה הסכום ייספר בגבייה אבל לא ביתרה של אף חשבון.'}
        >
          <select
            id="pay-account" value={accountId} disabled={isOffset}
            onChange={(event) => setAccountId(event.target.value)}
          >
            <option value="">בלי קופה</option>
            {accounts.map((account) => (
              <option key={account.id} value={account.id}>{account.name}</option>
            ))}
          </select>
        </Field>
        {chosen?.kind === 'personal' && (
          <p className={styles.warnNote}>זה חשבון פרטי של חבר קאמפ, לא קופה של הקאמפ.</p>
        )}

        <Field label="הערה" htmlFor="pay-note">
          <textarea
            id="pay-note" rows={2}
            placeholder="לא חובה — חוץ מקיזוז, שם חייבים לכתוב מול מה קוזז"
            value={note} onChange={(event) => setNote(event.target.value)}
          />
        </Field>

        {error && <p className={styles.error} role="alert">{error}</p>}
        {saved && <p className={styles.saved} role="status">{saved}</p>}
      </form>

      <section className={styles.previous}>
        <h3>תשלומים קודמים</h3>
        {row.payments.length === 0 ? (
          <p className={styles.muted}>אין עדיין תשלומים.</p>
        ) : (
          <ul>
            {row.payments.map((entry) => (
              <li key={entry.id}>
                <bdi>{formatILS(entry.amountAgorot)} ₪</bdi>
                <span>{entry.channel}</span>
                <bdi>{formatShortDate(entry.paidOn)}</bdi>
                {entry.note && <span className={styles.muted}>{entry.note}</span>}
                {entry.accountId === null && entry.channel !== 'קיזוז' && (
                  <span className={styles.muted}>בלי קופה</span>
                )}
              </li>
            ))}
          </ul>
        )}
      </section>

      <Banner
        tone="neutral"
        action={(
          <Link
            className={styles.btn}
            href={feesHref({ season: seasonId, view, exception: row.personId })}
          >
            הגדרת חריג
          </Link>
        )}
      >
        <Icon name="info" size={16} />
        {' רוצים לשנות את הסכום עצמו ולא לרשום תשלום? זה חריג, והוא מחייב סיבה — '}
        {'כדי שבעוד שנה יהיה אפשר לדעת למה.'}
      </Banner>
    </Drawer>
  );
}
```

```tsx
/** One member's flat rate. Never the season's — a button must not do more
 *  than it says (see the comment on `issueDueForAction`). */
export function IssueDueButton({ personId, seasonId, flatRateAgorot }: {
  personId: string; seasonId: string; flatRateAgorot: number;
}) {
  const router = useRouter();
  const [pending, setPending] = useState(false);
  const [error, setError] = useState<string | null>(null);

  async function issue() {
    setError(null);
    setPending(true);
    try {
      const result = await issueDueForAction(personId, seasonId);
      if (result.ok) router.refresh();
      else setError(result.error);
    } finally {
      setPending(false);
    }
  }

  return (
    <>
      <button type="button" className={styles.btn} onClick={issue} disabled={pending}>
        הנפקת חיוב <bdi>{formatILS(flatRateAgorot)} ₪</bdi>
      </button>
      {error && <p className={styles.error} role="alert">{error}</p>}
    </>
  );
}
```
