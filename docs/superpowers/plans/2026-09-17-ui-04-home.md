# בית — The Home Screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `/` from a dues-only landing page into the screen a lead opens to
decide what to do next: four figures they can act on — how much of the dues is
in, how much cash the camp holds, what is owed in both directions, and how many
task places are filled — then the לטיפול preview, the tasks still short of
people, and who has not paid, by name. Today's page shows no money at all and
hard-codes `seasons[0]`.

**Architecture:** One summary call for the whole page. `src/lib/overview/summary.ts`
composes the aggregates each domain already exports — `seasonFeeSummary`,
`accountBalances`, `unattributedAgorot`, `listObligations`, `unnamedObligations`,
`coverageFor`, `listUnlinkedNames` — into a single `SeasonOverview`, exactly as
Wave 1's `seasonMoneySummary` does for `/money`. The page awaits it once and
renders; no card issues its own query. Two figures the libraries cannot produce
yet are added where they belong: an open-places aggregate in
`src/lib/work/coverage.ts`, and the unpaid roster rows in
`src/lib/fees/summary.ts` (built from rows that function already reads, so it
costs no query). The route moves into a `(home)` route group so it can own a
`loading.tsx` skeleton without imposing it on every other admin page.

**Tech Stack:** Next.js 16.3.4 (App Router, React 19 Server Components), Drizzle
ORM on Postgres, PGlite for database-backed tests, Vitest +
@testing-library/react, CSS Modules. No new dependencies (R1).

**Spec:** `docs/superpowers/specs/2026-09-17-ui-redesign-design.md` — requirement
**D1**, plus **E1–E3** as they apply to this screen. Rulings R1, R3, R5, R6, R7,
R9, R11, A9–A12 are binding here.

## Global Constraints

Every task's requirements implicitly include all of these.

- **No new runtime dependencies (R1).** No component library, no icon package,
  no chart package, no date library. If a figure needs a helper, write it.
- **Server Components by default (R7).** This screen adds no client component.
  If one becomes unavoidable, it states in a comment why it is a client
  component — and that is a signal the design went wrong, not a licence.
- **The season is one global control (R5).** It arrives as `?season=<uuid>` and
  is read through plan 02's shared helper. The string `seasons[0]` must not
  appear anywhere in this plan's output; a test asserts that on the page source.
- **Every figure links to the page that can change it.** This is the rule the
  current `page.tsx` states in its own doc-comment, and it survives the
  redesign. A number a lead cannot act on belongs in a report, not here.
- **A card that would always read zero is not shown.** Also from the current
  page's comments: "a dashboard that always shows 0 outstanding items trains
  the reader to stop looking at that row." The rule is carried in the *type* —
  each figure is nullable, and `null` means "there is nothing here to report",
  not "zero".

  learned this the hard way (see its own test, "invites action instead of bare
  empty tables"). Every empty region on this screen names the season by name

- **Money is integer agorot in JS and `numeric(12,2)` in Postgres.**
  `src/lib/money.ts` (`toAgorot`, `fromAgorot`, `sumAgorot`, `formatILS`) is the
  only converter. Never float-arithmetic on money.
- **Money renders as `<bdi>{formatILS(agorot)} ₪</bdi>` (A11)** — one helper,
  symbol last, inside `<bdi>`, never string-concatenated with a sign. Direction
  is carried by the label or column, never by a minus sign.
- **Hebrew RTL throughout, logical properties only (A10).** `padding-inline`,
  `border-block-end`, `inset-inline-start`, `margin-inline-start: auto`. Never
  `left`/`right`, except a numeric column's documented `text-align: right`.
- **Hebrew copy is reused verbatim (E5).** Where a sentence already exists on

- **No gendered verb about a member.** The mock writes "שילמה 500" and

- **Admin-only.** The page calls `requireAdmin()` first and `notFound()` when it

### Task 1: Coverage counts places, not tasks

`uncoveredTasks` answers "which tasks are short". The home's fourth figure asks
a different question — "how many of the season's places are filled" — and there
is no aggregate for it. It goes in `src/lib/work/coverage.ts`, beside the rows
it folds, so `/tasks` (D9) can use the same number and the two screens can
never disagree.

**Ruling (binding):** two exports, not one. `summarizeCoverage(rows)` is pure
and folds rows the caller already holds; `coverageTotals(db, seasonId)` is the
convenience for a caller that holds none. `seasonOverview` uses the pure one, so
the home reads `coverageFor` exactly once for both the fraction and the gap
list — a `coverageTotals(db, …)` call beside a `uncoveredTasks(db, …)` call
would run the same two queries twice, which is the per-card query this whole
plan exists to avoid.

**Ruling (binding):** the fraction is capped per task and counts open tasks only.

1. `placesFilled` adds `Math.min(accepted, peopleNeeded)`. A shift needing 2
   with 4 accepted contributes 2. Uncapped, a season could report "34 of 32
   places filled" while six tasks stand empty, and the figure would be worse
   than no figure.
2. Only `status === 'open'` rows contribute to either half. `TaskCoverage.uncovered`
   is already defined that way (`task.status === 'open' && accepted < peopleNeeded`),
   and counting a cancelled task's places would put the denominator permanently
   out of reach.

**Files:**

- Consumes: `TaskCoverage`, `coverageFor` (this module); `AnyDb` from `@/lib/db-types`.

```ts
export interface CoverageTotals {
  /** Places on open tasks. A done or cancelled task has no place to fill. */
  placesNeeded: number;
  /** Accepted-or-done assignments, capped per task at that task's peopleNeeded. */
  placesFilled: number;
  /** Open tasks still short of their peopleNeeded. */
  uncoveredCount: number;
  /** Open tasks counted. */
  openTaskCount: number;
}

/**
 * "16 מתוך 32 מקומות" — the season's staffing as one fraction.
 *
 * Pure, over rows the caller already holds, because the home screen needs both
 * this fraction and the list of gaps from the same `coverageFor` read. A
 * database-taking version beside `uncoveredTasks` would run the same two
 * queries twice for one card.
 *
 * Capped per task: a shift needing two with four accepted contributes two.
 * Uncapped, an over-staffed task borrows places from an empty one and the
 * screen reports more filled places than the season has, while the gaps it is
 * supposed to surface stand untouched.
 *
 * Open tasks only, matching `TaskCoverage.uncovered`'s own definition. A
 * cancelled task's places can never be filled, so counting them would put the
 * fraction permanently out of reach and make a fully staffed season look short.
 */
export function summarizeCoverage(rows: TaskCoverage[]): CoverageTotals {
  let placesNeeded = 0;
  let placesFilled = 0;
  let uncoveredCount = 0;
  let openTaskCount = 0;

  for (const row of rows) {
    if (row.status !== 'open') continue;
    openTaskCount += 1;
    placesNeeded += row.peopleNeeded;
    placesFilled += Math.min(row.accepted, row.peopleNeeded);
    if (row.uncovered) uncoveredCount += 1;
  }

  return { placesNeeded, placesFilled, uncoveredCount, openTaskCount };
}

/** The same fraction for a caller that holds no rows — the task board (D9). */
export async function coverageTotals(
  db: AnyDb, seasonId: string,
): Promise<CoverageTotals> {
  return summarizeCoverage(await coverageFor(db, seasonId));
}
```

### Task 2: The fee summary says who has not paid, not just how many

`seasonFeeSummary` already reads the roster, the dues and the payments, computes
`unpaidCount`, and then throws away every name it just held. The home screen
needs those names. Producing them from `listSeasonFees` instead would cost two
queries per roster member (`settlementFor` and `listPayments` inside its loop) —
seventy queries for a thirty-five-person camp, to render five rows.

**Ruling (binding):** `unpaid` is built in the same pass that computes
`unpaidCount`, so the count and the list are the same fact and cannot disagree.
The dues read gains an `innerJoin` on `persons` for the display name; that is
the same three queries, not a fourth — and it means a due issued to someone who
has since left the roster still carries a name rather than a bare uuid.

**Ruling (binding):** ordered by `outstandingAgorot` descending, then by
`displayName`. Collection happens in runs (D5), and a run starts with the
largest outstanding; ties break by name so the order is stable between renders.

### Task 3: One summary call for the whole home screen

**Ruling (binding):** the home reads exactly one aggregate,
`seasonOverview(db, seasonId)`, and never a query per card. This is the pattern
Wave 1 established for `/money` in `src/lib/money/summary.ts`, whose own
doc-comment states the reason: "the page is a server component, and a summary
that forces it into a second round trip to fill a hole is a data-shape defect,
not a page defect."

**Ruling (binding):** `seasonOverview` composes the domain aggregates directly
rather than calling `seasonMoneySummary`. Reusing that one would drag in
`duesFundingIdentity` and `ledgerTotals` — five queries whose results this
screen never shows. One call per *page* is the rule; one summary shared by two
pages with different needs is not the same thing.

What it composes, and why each:

| call | gives | queries |
|---|---|---|
| `seasonFeeSummary(db, seasonId)` | the dues figure, the unpaid rows, roster size, flat rate | 4 |
| `accountBalances(db)` | the cash figure. **Camp-wide**, never season-scoped — a קופה does not reset at the burn | 3 |
| `unattributedAgorot(db, seasonId)` | money the system holds and cannot place | 3 |
| `listObligations(db, { seasonId })` | both directions in one read, partitioned in JS rather than by two queries | 2 |
| `unnamedObligations(db)` | camp-wide, deliberately not filtered out of the season list — see `SeasonMoneySummary.unnamed`'s comment: a season-less unnamed row matches no `season_id = $1` and would otherwise appear on no season's page | 2 |
| `coverageFor(db, seasonId)` | read once, folded by `summarizeCoverage` and filtered for the gap list | 2 |
| `listUnlinkedNames(db)` | the one register-shaped fact that exists before plan 05 | 1 |

**Ruling (binding):** every figure is nullable, and `null` means "there is
nothing here to report". This is the current page's own rule — "a dashboard that
always shows 0 outstanding items trains the reader to stop looking at that row"
— moved out of the JSX and into the type, so a card cannot be drawn by accident
and the rule is testable without rendering anything. The four conditions:

- `dues` is null when `expectedAgorot === 0`: no due has been issued, so there
  is no collection to report and "0 מתוך 0" is not a figure.
- `cash` is null when there is no account **and** nothing unattributed. An
  unattributed shekel with no account anywhere is precisely when the card
  matters most, so it is not enough that `accounts` is empty.
- `debts` is null when both directions are settled to zero and nothing is
  unnamed. A fully settled debt still exists, and reporting it as `0 ₪` teaches
  the reader to skip the row that will one day say 6,864.
- `coverage` is null when the season has no open task.

```ts
import type { AnyDb } from '@/lib/db-types';
import type { ObligationDirection } from '@/db/schema/money';
import { seasonFeeSummary } from '@/lib/fees/summary';
import type { UnpaidMember } from '@/lib/fees/summary';
import { accountBalances, unattributedAgorot } from '@/lib/money/accounts';
import { listObligations, unnamedObligations } from '@/lib/money/obligations';
import { coverageFor, summarizeCoverage } from '@/lib/work/coverage';
import type { CoverageTotals, TaskCoverage } from '@/lib/work/coverage';
import { listUnlinkedNames } from '@/lib/members/identity';

export interface DuesFigure {
  expectedAgorot: number;
  collectedAgorot: number;
  outstandingAgorot: number;
  unpaidCount: number;
  /** Unpaid members who have paid something — the mock's "3 שילמו חלקית". */
  partlyPaidCount: number;
  /** Roster members with no due row at all. Surfaced, never silently skipped. */
  missingDuesCount: number;
  unpaid: UnpaidMember[];
}

export interface CashFigure {
  /** Camp-wide. A קופה does not reset at the burn, so switching seasons must
   *  never appear to change how much cash the camp holds. */
  totalAgorot: number;
  accountCount: number;
  /** Money in with no account named, plus dues payments with no account.
   *  Outflow is deliberately excluded: adding "money that left for somewhere
   *  unknown" to "money that arrived from somewhere unknown" produces a number
   *  that is a quantity of nothing — see `unattributedAgorot`'s own comment.
   *  The outflow is on /money, where it has a sentence of its own. */
  unattributedInAgorot: number;
}

export interface DebtsFigure {
  /** Sums of `outstandingAgorot`, not `amountAgorot` — a partly settled debt
   *  must not be shown as though nothing had been paid against it. */
  campOwesAgorot: number;
  owedToCampAgorot: number;
  /** Camp-wide and every direction, including debts with no season at all. */
  unnamedCount: number;
}

/**
 * Everything the home screen needs, in one call.
 *
 * Each figure is nullable, and `null` means "there is nothing here to report".
 * That is not a formatting nicety: a card that would always read zero teaches
 * its reader to stop looking at the row, and the row is the one that will one
 * day say 6,864 ₪. Keeping the rule in the type means the page cannot draw such
 * a card by accident, and the rule can be tested without rendering anything.
 */
export interface SeasonOverview {
  seasonId: string;
  seasonName: string;
  /** Roster size. Known even before a single due has been issued. */
  memberCount: number;
  flatRateAgorot: number;
  /** Null when no due has been issued: there is no collection to report. */
  dues: DuesFigure | null;
  /** Null when there is no account and nothing unattributed. */
  cash: CashFigure | null;
  /** Null when both directions are settled and nothing is unnamed. */
  debts: DebtsFigure | null;
  /** Null when the season has no open task. */
  coverage: CoverageTotals | null;
  /** Every open task still short of people, biggest gap first. */
  understaffed: TaskCoverage[];
  /** Camp-wide. The one register-shaped fact that exists before plan 05. */
  unlinkedCount: number;
}

/**
 * One call, seven reads, no query per card.
 *
 * This follows `seasonMoneySummary`'s pattern rather than reusing it: that
 * summary also computes the dues/fundraising identity and the ledger totals,
 * neither of which this screen shows. One summary per page, composed from each
 * domain's own aggregate — never one aggregate stretched across two pages that
 * need different halves of it.
 */
export async function seasonOverview(
  db: AnyDb, seasonId: string,
): Promise<SeasonOverview> {
  const fees = await seasonFeeSummary(db, seasonId);
  const accounts = await accountBalances(db);
  const unattributed = await unattributedAgorot(db, seasonId);
  // Both directions from one read, partitioned here. Two filtered queries
  // would be two round trips for one card.
  const obligations = await listObligations(db, { seasonId });
  // Camp-wide, and deliberately not derived from `obligations` above: a debt
  // with no season matches no `season_id = $1`, so a season-scoped read would
  // leave it on no screen at all.
  const unnamed = await unnamedObligations(db);
  const coverageRows = await coverageFor(db, seasonId);
  const unlinked = await listUnlinkedNames(db);

  const outstandingIn = (direction: ObligationDirection): number => obligations
    .filter((row) => row.direction === direction)
    .reduce((total, row) => total + row.outstandingAgorot, 0);

  const campOwesAgorot = outstandingIn('camp_owes');
  const owedToCampAgorot = outstandingIn('owed_to_camp');
  const unattributedInAgorot = unattributed.inAgorot + unattributed.paymentsAgorot;
  const coverage = summarizeCoverage(coverageRows);

  const understaffed = coverageRows
    .filter((row) => row.uncovered)
    // Biggest gap first: six missing people is a different problem from one,
    // and the panel shows only the first few rows.
    .sort((a, b) => (b.peopleNeeded - b.accepted) - (a.peopleNeeded - a.accepted)
      || a.title.localeCompare(b.title, 'he'));

  return {
    seasonId,
    seasonName: fees.seasonName,
    memberCount: fees.memberCount,
    flatRateAgorot: fees.flatRateAgorot,
    dues: fees.expectedAgorot === 0 ? null : {
      expectedAgorot: fees.expectedAgorot,
      collectedAgorot: fees.collectedAgorot,
      outstandingAgorot: fees.outstandingAgorot,
      unpaidCount: fees.unpaidCount,
      partlyPaidCount: fees.unpaid.filter((row) => row.paidAgorot > 0).length,
      missingDuesCount: fees.missingDues.length,
      unpaid: fees.unpaid,
    },
    cash: accounts.length === 0 && unattributedInAgorot === 0 ? null : {
      totalAgorot: accounts.reduce((total, row) => total + row.balanceAgorot, 0),
      accountCount: accounts.length,
      unattributedInAgorot,
    },
    debts: campOwesAgorot === 0 && owedToCampAgorot === 0 && unnamed.length === 0
      ? null
```

  ```ts
export interface PreviewItem {
  id: string;
  icon: IconName;
  title: React.ReactNode;
  detail: React.ReactNode;

  source?: string;
  ```

```tsx
 *
 * `items` being empty is not by itself good news — it is good news only when
 * `total` is zero too. All-clear is the one empty state that celebrates (C10),
 * and celebrating over a queue nobody has looked at is how a screen starts
 * lying to the person reading it.
 */
export function InboxPreview({ items, total, remainder, seasonName, href }: {
  items: PreviewItem[];
  total: number;
  remainder: React.ReactNode | null;
  seasonName: string;
  href: string | null;
}) {
  return (
    <section className={styles.panel}>
      <div className={styles.panelHead}>
        <Icon name="inbox" size={16} />
        <h2>לטיפול</h2>
        {total > 0 ? (
          <Pill tone="brand"><bdi>{total}</bdi> החלטות</Pill>
        ) : null}
        <span className={styles.panelLead}>
          המערכת לא מנחשת. אלה ההכרעות שממתינות לכם.
        </span>
        {href ? (
          <Link className={styles.more} href={href}>לכל הרשימה ←</Link>
        ) : null}
      </div>

      {items.length === 0 && total === 0 ? (
        <div className={styles.emptyBody}>
          <EmptyState
            kind="all-clear"
            title="אין מה להכריע"
            body={<>כל מה שיובא ל{seasonName} שויך ואושר.</>}
          />
        </div>
      ) : (
        <ul className={styles.rows}>
          {items.map((item) => (
            <li key={item.id} className={styles.row}>
              <Icon name={item.icon} size={15} />
              <span className={styles.rowMain}>
                <span className={styles.rowTitle}>
                  {item.title}
                  {item.pill ? (
                    <Pill tone={item.pill.tone}>{item.pill.text}</Pill>
```
